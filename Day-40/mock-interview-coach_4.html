How this was built ▾

System prompt design

The Claude call underneath this app behaves as a single persistent character — a professional interview coach named "The Panel" — with a strict output contract per turn: either the next interview question, or feedback on the last answer followed by the next question. Feedback always follows a fixed shape: a one-word verdict (Strong / Solid / Needs Work / Weak), 2–3 sentences of specific critique tied to what was actually said, and one concrete rewrite suggestion. This constrains the model to give actionable coaching rather than generic encouragement — a common failure mode when LLMs play "supportive coach."

Edge cases handled explicitly in the prompt: empty or one-word answers get called out directly rather than praised; off-topic or abusive input is redirected back to the interview without moralizing; and if the candidate asks a genuine clarifying question, the coach answers briefly in-character before re-asking.

Why the UI choices fit this use case

A generic chatbot box would undersell the premise — this is meant to feel like sitting across from someone, not messaging a bot. The stage-light gradient, round-dot progress tracker, and desk-style setup card borrow visual language from an actual interview room. Verdict chips give a fresher an instant read on each answer without parsing paragraphs, while the underlined "try this instead" block keeps the fix concrete and separate from the critique.

How to extend it

  • Tools: add a web-search-backed step so the coach can pull real, current interview questions for a specific company before the session starts.
  • Memory: persist session transcripts to a real backend/DB so returning users see progress across sessions and recurring weak spots.
  • Multi-step flows: split into distinct rounds (HR → technical → project deep-dive) with a summary report generated via a second Claude call at the end, scoring the full transcript instead of single answers.
  • Resume upload: accept a pasted resume alongside the JD so questions probe specific projects instead of generic ones.
