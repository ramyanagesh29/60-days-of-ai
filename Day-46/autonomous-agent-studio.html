🏗️ Architecture Overview — What Each Agent Does

      

        
📋 Planner
Reads the raw spec once and produces an implementation approach: edge cases to cover, structure, and a rubric emphasis. Runs once, before the loop begins.

        
⚡ Executor
Writes the first working draft of the code based on the Planner's approach. Runs once to seed round 1.

        
📈 Evaluator
Scores the current draft on correctness, quality, and efficiency (0–10 each) plus an overall score, and writes a structured report. Called fresh every round against the latest code.

        
🔍 Critic
Given the Evaluator's report and the code, identifies specific, actionable weaknesses the Improver should target next. Called every round after the Evaluator.

        
🛠️ Improver
Rewrites the code using the prior evaluation + critique + memory context. Only called when the Stop-Check does NOT fire — its output becomes next round's input to the Evaluator.

        
🧠 Memory Manager
Condenses each round's findings into a running memory string, so recurring issues (e.g. "always forgets edge case X") persist across rounds instead of being re-discovered.

        
✅ Final Reviewer
Fires once, only after the Stop-Check ends the loop. Reviews the final code and full history, confirms production-readiness, and writes the closing sign-off.

        
🚦 Stop-Check
Not an LLM call — a deterministic gate that runs every round in fixed order: (1) plateau, (2) threshold, (3) hard cap. Whichever fires first controls whether the loop continues to Improver or branches to Final Reviewer.

      

    


    
    

      
🚀 Extension Ideas

      

        
Add a Safety Monitor agent — run in parallel with the Evaluator to flag insecure patterns (eval(), unsanitized input, secrets) before code ever reaches Improver.

        
Multi-file / project scope — extend Executor and Improver to emit a file map instead of one function, with a dependency-aware Planner.

        
Tool use for real execution — give the Evaluator an actual sandboxed test runner instead of self-reported scoring, and feed real stack traces into the Critic.

        
Persistent memory across sessions — store the Memory Manager's output in localStorage/a vector store so lessons carry over between unrelated runs.

        
Human-in-the-loop gate — pause before Final Reviewer and let a person approve/reject/edit, feeding their notes back into one more Improver pass.

        
Adaptive stopping — let the Planner set the plateau delta and threshold dynamically based on task difficulty instead of fixed interview answers.
